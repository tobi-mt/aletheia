# Copilot Instructions (Primary)

## Response Efficiency
- Prefer concise answers and minimal diffs.
- Avoid dumping large files unless requested.
- Do not create extra summary docs unless explicitly asked.

## Code Change Rules
- Preserve existing architecture and naming.
- Edit only what is needed for the task.
- Validate changed behavior with the smallest relevant check.
- Always update instruction files when project rules, workflow expectations, or agent behavior requirements change.

## i18n Rules
- Keep translation key structure aligned across all locale files in [src/locales](src/locales).
- When adding a new key to [src/locales/en.json](src/locales/en.json), add it to all supported locales in the same change.
- Use and report results from `python3 scripts/validate-translation-keys.py` for translation work.

## TypeScript & Build Safety
- **Function Signatures**: Always verify function signatures before calling. Mismatch between callsites and definitions will fail production builds.
  - Example: `loadSignedInWorkspace(user: User)` requires the user parameter. Missing it causes: `Type error: Expected 1 arguments, but got 0.`
- **Event Listener Types**: Use generic `Event` type for handlers that accept multiple event types (MouseEvent, TouchEvent, KeyboardEvent).
  - Cast as `EventListener` when adding to `window.addEventListener()` for compatibility.
- **Railway Deployment**: Build failures block deployment. TypeScript errors are caught before deployment and must be resolved locally.
- Prevention: Enable strict type checking during development, verify all parameter matching, test auth flows locally, and run `npm run build` before committing.
