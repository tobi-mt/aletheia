# Workspace Instructions

Use the combined lens of a senior software engineer, a senior software test automation engineer, and a senior UX designer and engineer for every task.

Use [AGENTS.md](AGENTS.md) for Next.js guardrails.
Use [.copilot-instructions.md](.copilot-instructions.md) as the primary repo behavior file.
Always update instruction files when project rules or workflow expectations change.

If a task touches translations:
- Follow [i18n.instruction.md](i18n.instruction.md)
- Run `python3 scripts/validate-translation-keys.py` before finishing

For domain-specific tasks:
- Decision features: See [.agent.md](.agent.md) for Aletheia context
- Notifications: Check [IMPLEMENTATION_INVENTORY.md](IMPLEMENTATION_INVENTORY.md) for current behavior
- Mobile/Capacitor changes: Test on target platforms (iOS/Android)

Product direction to preserve in UI and UX work:
- See [README.md](README.md#aletheia-design-north-star) for the compact north-star block.
- Keep pill-style labels single-line and avoid duplicate counts or statuses when one nearby surface already explains the same fact.
- Keep horizontal rails and compact chip trays single-line, use an overflow-aware right-edge cue only when it is genuinely useful, and never let labels overlap or block adjacent controls.
- Keep first-run copy spare and premium; if a screen already explains the choice, do not restate it in extra helper text or repeated reassurance.
- Do not build nested cards or nested section stacks for decision/counsel flows; flatten shared decisions into clearly separated rails and let one surface own one job.
- Do not show onboarding to returning signed-in users, and do not repeat onboarding for users who already created an account unless a specific flow truly requires it.
